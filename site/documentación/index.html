    Parte II. Registro del proceso de desarrollo

    Documentar el proceso de desarrollo aplicando Scrum, siguiendo los puntos de la guía que nos da el docente en la Plataforma, y que se puede consultar abriendo el siguiente enlace:

    https://presencial.uagrm.edu.bo/pluginfile.php/4029333/mod_resource/content/3/EnfoqueScrumSmainn.pdf

    Para modelar la arquitectura del software usar los diagramas del modelo C4 .

    Usar UML para todos los demás modelos.

    Durante el proceso de desarrollo se debe hacer al menos estos cuatro modelos:

    1. Modelo de arquitectura.
      • Para modelar la arquitectura del software se debe usar el modelo C4.
      • En el modelo C4, el modelo de la arquitectura del software se expresa mediante diagramas de contexto, de contenedores, de componentes y de código.
    2. Modelo de datos.
      • El modelo de datos no es más que el modelo de la base de datos.
      • El modelo de la base de datos es el mismo que se realiza en Base de Datos I.
      • Hacer el modelo de la base de datos es hacer los siguientes tres modelos:
        • Modelo conceptual, expresado como un diagrama de clases.
        • Modelo lógico, expresado como tablas resultado de mapear las clases del modelo conceptual a tablas del modelo relacional de la base datos. Estas tablas muestran el nombre de la tabla, sus atributos y cuáles atributos son llaves primarias (primary keys) y cuáles son llaves foráneas (foreign keys).
        • Modelo físico, expresado como el código SQL necesario para crear la base de datos en el gestor de base de datos del software. IMPORTANTE: Para el 2do Parcial el docente exige utilizar un gestor de bases de datos como PostgreSQL o superior. No usar MySQL.
    3. Modelo de procesos.
      • No es necesario modelar todos los procesos del software.
      • Modelar únicamente los procesos que tienen una lógica no trivial.
      • Por ejemplo, no es necesario modelar la lógica para hacer operaciones tipo CRUD (create, read, update, delete) sobre la base de datos.
      • Para modelar los procesos se pueden usar diagramas UML, como: diagramas de secuencia, de estados, de tiempo, etc.
    4. Modelo de interfaces.
      • Es el modelo de las interfaces de usuario.
      • Pueden expresarse como bocetos, prototipos o mockups realizados usando herramientas como Figma o draw.io.
